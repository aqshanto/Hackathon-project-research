## FinCluster Node Features

These are not PaySim columns. They will be added by the controlled experiment:

- `node_profile`
- `cpu_limit`
- `memory_limit`
- optional `concurrency_limit` after pilot design

Dynamic runtime features such as queue length or current utilization should be added only if they are measured before routing and deliberately included in the research question.

## Dataset/Control Columns That Are Not ML Input Features

- `transaction_id` - required for grouping, traceability, idempotency, and audit; not a predictor
- repetition/run number - measurement metadata; not a predictor for live inference
- pipeline version - reproducibility metadata

## Initially Excluded Features

### `nameOrig`

Excluded from the first model because it is a raw high-cardinality account identifier and may encourage memorization without useful generalization.

### `nameDest`

Excluded from the first model for the same high-cardinality identifier/generalization reason.

### `newbalanceOrig`

Excluded because it represents post-transaction information and can create future-information/data-leakage risk for a pre-routing prediction task.

### `newbalanceDest`

Excluded for the same post-transaction leakage reason.

### `isFraud`

Excluded from the service-time model. Fraud status is not equivalent to processing workload.

### `isFlaggedFraud`

Initially excluded. It is a fraud/simulator-derived signal, not measured workload ground truth. It may only be reconsidered in a later explicitly defined pre-routing verification experiment.

## Primary Target

```text
service_time_ms
```

This target does **not** exist in PaySim. It will be generated by executing selected transactions through the controlled FinCluster reference processing pipeline on controlled node profiles.

## VPN Feature

PaySim does not provide a verified VPN column in the current schema. VPN is therefore **not** part of the current research feature set.

If VPN is ever introduced later by the simulator, it must be explicitly documented as a synthetic contextual feature and evaluated separately.

## Important Methodological Rules

- `isFraud` is not Heavy.
- `service_time_ms` is target `y`, not input `X`.
- only information available before routing can be considered an online prediction feature;
- all node observations belonging to the same `transaction_id` must remain in the same train/validation/test split;
- raw PaySim data must be preserved unchanged; feature exclusion applies to model input, not deletion from the source file.
