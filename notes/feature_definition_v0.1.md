# FinCluster Feature Definition v0.1

## 1. Prediction Task

```text
X = pre-routing transaction features + controlled node features
y = measured service_time_ms
```

The model must never receive `service_time_ms` as an input feature.

## 2. Candidate PaySim Transaction Features

| Feature | Initial decision | Reason |
|---|---|---|
| `type` | Include | Transaction type can select different processing paths and validation work. |
| `amount` | Include | Transaction amount may affect limit/policy checks and conditional processing. |
| `oldbalanceOrg` | Include | Pre-transaction origin/source balance is available before execution in the dataset. |
| `oldbalanceDest` | Include | Pre-transaction destination balance can be considered when the routing layer is assumed to receive it. This assumption must be documented. |
| `step` | Candidate | Encodes PaySim simulation time. Keep initially, then evaluate usefulness/ablation because it is not direct computational workload. |

## 3. FinCluster Node Features

These columns are generated by the controlled experiment rather than PaySim:

- `node_profile`
- `cpu_limit`
- `memory_limit`
- optional `concurrency_limit`

Potential later dynamic features, only if accurately measured before routing:

- current queue length;
- current CPU utilization/load band;
- current memory utilization;
- node health state.

The first pilot should prefer static controlled node-profile features to keep the initial measurement problem simple.

## 4. Non-Predictor Control and Metadata Columns

### `transaction_id`

Required for:

- unique transaction identity;
- grouped train/validation/test splitting;
- idempotency/duplicate protection;
- experiment traceability;
- later safe-reroute attempt tracking.

It is **not** an ML input feature.

### `attempt_id` / repetition index

May be recorded for raw measurement attempts but is not a live prediction feature.

### Pipeline/configuration metadata

Pipeline version, dataset version, node-profile version, random seed, host information, and software versions are required for reproducibility but are not automatically ML features.

## 5. Initially Excluded PaySim Features

| Feature | Initial decision | Reason |
|---|---|---|
| `nameOrig` | Exclude | Raw high-cardinality source identifier; memorization/generalization/privacy concern. |
| `nameDest` | Exclude | Raw high-cardinality destination identifier; memorization/generalization/privacy concern. |
| `newbalanceOrig` | Exclude | Post-transaction value; future-information/data-leakage risk for pre-routing prediction. |
| `newbalanceDest` | Exclude | Post-transaction value; future-information/data-leakage risk. |
| `isFraud` | Exclude | Fraud status is not processing workload and must not be treated as Heavy. |
| `isFlaggedFraud` | Exclude initially | Fraud/simulator-derived flag, not measured workload ground truth; may only be reconsidered in a specifically justified pre-routing verification experiment. |

## 6. VPN and Other Non-PaySim Features

The current PaySim schema does not contain a verified VPN field. Therefore `is_vpn`/VPN is not used in the current research benchmark.

A simulator-generated VPN/device/network-risk feature could be studied later, but it must be labelled as synthetic and must not be presented as an original PaySim column.

## 7. Target

```text
service_time_ms
```

Definition:

> server-side time required to execute the documented FinCluster reference processing pipeline for one transaction on one controlled node profile, measured under the locked experiment protocol.

The target is produced from actual controlled execution measurements. Multiple raw runs are summarized using the median per transaction-node pair after warm-up.

## 8. Leakage Rule

**Golden rule:** if a value would not be available when the router must make its decision, it must not be used as a live prediction feature.

## 9. Grouped Split Rule

All node-level observations originating from one `transaction_id` must stay in the same train/validation/test group.

Incorrect:

```text
TX100 + Low    -> Train
TX100 + Medium -> Train
TX100 + High   -> Test
```

Correct:

```text
TX100 + all node observations -> one split only
```
