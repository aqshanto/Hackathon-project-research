# Workload Definition - Current Research Interpretation

## 1. Primary Research Target

The research no longer uses handcrafted Light/Heavy labels as the primary target.

The primary target is continuous measured processing time:

```text
service_time_ms
```

This target is generated by executing the FinCluster reference processing pipeline on controlled node profiles.

## 2. Why the Old Handcrafted Labels Were Replaced

Earlier Heavy/Light labels were created from rules such as amount, transaction type, VPN, account age, or other synthetic indicators. When the same information is used both to generate the label and train the model, the model can simply rediscover the handcrafted rule.

That approach is preserved only as project history and is not the preferred paper methodology.

## 3. Secondary Workload Bands

For interpretability, measured or predicted service time may later be summarized as:

- Light
- Moderate
- Heavy

These bands are **secondary**. They do not replace the continuous regression target.

Desired presentation example:

```text
Predicted Service Time: 37.386 ms
Workload Band: Moderate
```

## 4. K-Means Role

K-Means may be evaluated as an unsupervised method for grouping measured/reference service-time values into clusters.

If three clusters are scientifically supported:

```text
lowest-latency cluster  -> Light
middle-latency cluster  -> Moderate
highest-latency cluster -> Heavy
```

The study must not force three clusters merely because the UI wants three labels. Cluster separation and stability must be checked.

Possible clustering-quality checks:

- Silhouette Score
- Davies-Bouldin Index
- Calinski-Harabasz Score
- cluster stability across seeds/resamples
- domain interpretability

If the distribution does not support stable clusters, continuous service time or another justified banding strategy should be retained instead.

## 5. KNN Is Different

KNN Regressor is a supervised model candidate that predicts `service_time_ms` from labeled transaction-node observations.

KNN and K-Means are not direct competitors:

```text
KNN Regressor -> predicts service_time_ms
K-Means       -> groups existing service-time values
```

If a separate workload-classification experiment is ever added later, KNN Classifier would require already-defined labels.

## 6. Reference-Node Option for Transaction-Level Bands

A transaction can have different service times on Low, Medium, and High nodes. Therefore a transaction-level workload band can become ambiguous if every node-specific latency is mixed together.

A proposed solution is to choose one fixed **reference node** (for example the final Medium profile) and derive transaction-level workload bands from service times measured/predicted on that reference profile.

This is proposed, not yet finalized.

## 7. Important Boundary

Fraud is not workload:

```text
isFraud != Heavy
```

PaySim fraud labels are not used as the service-time target or as automatic workload labels.
